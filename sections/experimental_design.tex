\subsection{Forecasting task}
\label{sec:exp:task}

% SCHREIBE: Absatz Prognoseaufgabe (5-7 Sätze).
%  - Was die Modelle ausgeben: für jedes Land i und jeden Entscheidungsmonat
%    t drei bedingte Quantile der Spread-Änderung Delta s_{i,t+1} einen
%    Monat voraus, auf den Stufen {0.1, 0.5, 0.9}.
%  - Daraus wird das zentrale 80%-Prognoseintervall, also alpha = 0.20.
%    Das 0.5-Quantil ist der Punktschätzer.
%  - WARUM ausgerechnet {0.1, 0.9} — das ist eine Designentscheidung, die
%    du begründen musst: TiRex und TiRex-2 geben nur Dezile aus. 0.1 und
%    0.9 sind damit die breitesten Stufen, die JEDES Modell im Vergleich
%    ohne Extrapolation liefern kann. Die Wahl richtet sich also nach dem
%    schwächsten Glied der Vergleichskette, nicht nach Bequemlichkeit.
%  - Die trainierten Quantilmodelle (die Deep Models und LightGBM) werden
%    mit dem Pinball-Loss gefittet. Die Gleichung \eqref{eq:pinball} steht
%    schon da, sie bleibt unverändert — ein Satz Hinführung reicht.
%  - Die Punktprognosemodelle (Random Walk, ARIMA) haben keinen Quantil-
%    Loss. Sie bauen ihr Intervall aus den empirischen Quantilen ihrer
%    In-Sample-Residuen, die auf die Punktprognose addiert werden.
%  - PFLICHT: dazusagen, dass das ohne Verteilungsannahme auskommt. Das
%    ist der Grund, warum es zum verteilungsfreien Anspruch der Arbeit
%    passt, und kein Nebensatz.
%  NICHT hier: wie kalibriert wird (das ist \cref{sec:conformal}) und wie
%  ausgewertet wird (das ist \cref{sec:evaluation}).

For every country $i$ and every month $t$ three quantiles (0.1, 0.5, 0.9) for the change in spread $\Delta s_{i,t+1}$ with respect to the next month are predicted.
From the lower and upper quantile we create the 80$\%$ prediction interval, so $\alpha = 0.2$. The 0.5 quantile is our point estimator. TiRex and TiRex-2 only output deciles. For that reason we choose the widest possible quantiles all models could be compared on and ended up with 0.1 and 0.9. The trained models, neural networks and LightGBM, are trained on the pinball loss:
\begin{equation}
  \mathcal{L}(\hat{q}, y) \;=\;
  \frac{1}{|\mathcal{T}|}\sum_{\tau \in \mathcal{T}}
  \max\!\big(\tau\,(y - \hat{q}_\tau),\; (\tau - 1)(y - \hat{q}_\tau)\big).
  \label{eq:pinball}
\end{equation}
The models that only produce a point forecast (Random Walk, ARIMA) do not have a quantile loss. We create their prediction intervals from the respective empirical quantiles of their in-sample residuals that are added onto the point forecast. This works without a distribution assumption.

\subsection{Training regimes}
\label{sec:exp:regimes}

% SCHREIBE: Kurzer Führungssatz + die drei Regime + zwei Sätze Einordnung.
%  Die \begin{itemize} mit L / G / GF bleibt strukturell stehen, du
%  schreibst den Rahmen und die Erläuterungen darin neu.
%  - L (local): ein Modell pro Land, bis zu 277 Monatsbeobachtungen.
%  - G (global): ein Modell auf dem gepoolten Panel, bis zu 2770
%    Ländermonate. Die Länderidentität geht mit hinein — als gelerntes
%    Embedding bei den neuronalen Netzen, als native kategoriale Variable
%    bei LightGBM.
%  - GF (global fine-tuned): das globale Modell wird je Land vollständig
%    feingetunt, mit einem Zehntel der globalen Lernrate.
%  - WARUM diese drei und nicht zwei: sie spannen genau die Achse lokal ->
%    global -> spezialisiert auf. Das ist die Achse, an der RQ1 hängt.
%    Ein Satz dazu, dass der Vergleich dadurch fair wird, weil sich die
%    drei Regime nur in dieser einen Dimension unterscheiden.
%  - Abgrenzung zum Schluss: LightGBM hat nur L und G (Begründung kommt
%    erst in Block 7, hier nur die Tatsache). Die klassischen und die
%    Zero-Shot-Modelle laufen in einer einzigen Einstellung.
%    Querverweis \cref{tab:model_selection}.

We employ three training regimes per model where possible.
\begin{itemize}
  \item \textbf{L} (local): One model per country that is trained on up to 277 monthly observations.
  \item \textbf{G} (global): One model on the pooled panel trained on up to 2770 months, 277 per country. Country is a learned embedding in the neural networks and a native category in LightGBM.
  \item \textbf{GF} (global fine-tuned): The global model is fully fine-tuned per country with a tenth of the learning rate.
\end{itemize}
We choose this design because it allows a fair comparison between a local, a global and a specialized model. For LightGBM there is no fine-tuning equivalent so we only employ the L and G regimes here. The classical and zero-shot models have a single configuration (\cref{tab:model_selection}).

\subsection{Input sequences and scaling}
\label{sec:exp:sequences}

% SCHREIBE: Absatz Eingabe und Skalierung (4-5 Sätze).
%  - Was das Modell sieht: die Sequenz der letzten W monatlichen
%    Feature-Vektoren bis zum Entscheidungsmonat t. Daraus wird
%    Delta s_{t+1} geschätzt.
%  - Skalierung: z-Standardisierung pro Land und pro Feature, das Target
%    eingeschlossen.
%  - PFLICHT (das ist der eigentliche Punkt des Absatzes): der Skalierer
%    wird NUR auf dem Trainingsfenster des jeweiligen Refits gefittet.
%    Deshalb kann keine Zukunftsinformation über die Skalierung
%    hereinlecken. Ohne diesen Satz ist der ganze Absatz Beiwerk.
%  - Der eine fehlende Input (Griechenland 2015-07) wird um einen Monat
%    vorgetragen. Target und Evaluation werden NIE imputiert. Diesen
%    Unterschied klar benennen, er kommt in \cref{sec:conformal} wieder.
%  - Querverweis auf \cref{sec:data} für die Datenlücke selbst.

The forecast is done on the last $W$ monthly feature vectors up to the decision month $t$. From that $\Delta s_{i,t+1}$ is estimated. The input data is $z$-standardized per country and feature, the target included. The standardization is exclusively done on the training data of the current refit so there is no data leakage. The one missing input (Greece 2015-07) is forward filled (\cref{sec:data}). Target and evaluation are never imputed.




\subsection{Rolling refit and temporal evaluation}
\label{sec:exp:refit}

% SCHREIBE: Absatz Refit-Schema (5-6 Sätze).
%  - Alle Modelle werden alle 12 Monate auf einem expandierenden
%    Trainingsset neu trainiert.
%  - Mechanik: bei Trainings-Cutoff in Monat C prognostiziert dasselbe
%    Modell die Monate C+1 bis C+12, jeweils einen Schritt voraus und
%    jeweils nur mit den zu diesem Zeitpunkt verfügbaren Daten.
%  - Die ersten 114 Monate sind das minimale Trainingsset.
%  - Die Monate 115-150 haben eine DOPPELROLLE, und die gehört explizit
%    benannt: Burn-in für die Kalibrierung der Conformal-Methoden
%    (\cref{sec:conformal}) UND Validierungsset für die
%    Hyperparameteroptimierung.
%  - Testfenster: Monate 151-277, also 2015-10 bis 2026-04, das sind
%    127 Testmonate pro Land. Die 127 sind die Zahl, auf die sich das
%    ganze Results-Kapitel bezieht — hier sauber einführen.
%  - Querverweis \cref{tab:refit_blocks}.
% ZAHLEN AUS: die Tabelle im Kapitel selbst; 127 Monate auch in
%   sections/evaluation.tex (dort schon eingeführt) — Konsistenz prüfen.

All models are refit every 12 months on an expanding training set. At training cutoff in month $C$ the same model predicts the months $C+1$ to $C+12$ in one-step-ahead predictions using only the data available at the respective point in time. The first 114 months are the minimal training set. The burn-in set, months 115 to 150, serves as calibration set for the conformal methods (\cref{sec:conformal}) as well as validation set for the hyperparameter optimization. Months 151 to 277 are the test window, so 127 test months per country. The 127 months are the months all the results in the results chapter are based on (\cref{tab:refit_blocks}).

\subsection{Hyperparameter selection}
\label{sec:exp:hpo}

% SCHREIBE: Absatz HPO-Protokoll (5-6 Sätze).
%  - Aufteilung: Monate 1-114 Training, Monate 115-150 Validierung, für
%    alle getunten Modelle gleich.
%  - Danach werden die Hyperparameter eingefroren und die Modelle damit
%    neu trainiert. Kein Testfenster fließt in die Selektion ein.
%  - Der gemeinsame Informationshorizont: jedes TRAINIERBARE Modell mit
%    einem Informationshorizont ist auf höchstens 24 Monate begrenzt, so
%    dass kein Modell weiter zurückschauen kann als die anderen.
%  - PFLICHT (dein eigener Fix vom 03.08., Commit cb16d8d, aus Review
%    §1.3 — dieser Satz MUSS erhalten bleiben): TiRex und TiRex-2 sehen
%    die volle expandierende Level-Historie. Der 24-Monats-Cap gilt für
%    sie NICHT. Das ist ein Informationsvorteil der Zero-Shot-Modelle und
%    muss als solcher benannt werden, weil tirex2 dein Top-Modell ist.
%    Wenn du das streichst, holst du dir den Referee-Einwand zurück.
%    -> Das Wort "trainable" ist deshalb nicht kosmetisch.
%  - Selektionskriterium, wo überhaupt ein Loss minimiert wurde: mittlerer
%    Pinball-Loss auf der standardisierten Delta-Skala, über die Länder
%    gemittelt, über die Burn-in-Validierungsmonate.
%  - Ein Satz, warum auf der standardisierten Skala und nicht in Levels:
%    sonst dominiert ein Land mit hohem Spread-Niveau die Auswahl.

% ZAHLEN AUS: \cref{tab:app_protocol} (Sampler, Trial-Budget, Fenster).

The months 1 to 114 are used for training and the months 115 to 150 for validation. This stays consistent for all trained models. After that the hyperparameters are frozen and the models retrained with the same set every time. No data from a test window is used in the selection. Every trainable model with an information horizon is capped to at most 24 months so no model can see further back than the others. TiRex and TiRex-2 see the full expanding level history. The 24-month cap does not apply to them. This is an information advantage for the zero-shot models. The hyperparameter selection was done by minimizing the average pinball loss on the standardized $\Delta$ scale, averaged over all countries, on the burn-in/validation set. We use the standardized scale since otherwise countries with higher spread levels would dominate the selection.

\paragraph{LSTM, xLSTM.}

% SCHREIBE: Absatz Protokoll der beiden Deep Models (6-8 Sätze).
%  - Führungssatz: beide teilen dasselbe Protokoll und unterscheiden sich
%    nur in der Architektur. Das ist die Voraussetzung dafür, dass der
%    Skill-Unterschied der Zelle zugeschrieben werden kann und nicht der
%    Pipeline — dieselbe Ablations-Logik steht in \cref{sec:models:lstm},
%    hier nur kurz anreißen und verweisen.
%  - Tuning: Optuna, TPE-Sampler, Seed 42, 20 Startup-Trials, MedianPruner
%    (20 Startup-Trials, 3 Warm-up-Schritte), 100 Trials, eine Studie je
%    Regime (L und G).
%  - Innerhalb eines Trials: höchstens 100 Epochen, Early Stopping mit
%    Patience 15.
%  - Einfrieren der Epochenzahl aus dem Gewinner-Trial. Regime L: Median
%    der besten Epochen über die zehn Länder. Regime G: die beste Epoche.
%    Alle Refits trainieren dann diese feste Epochenzahl OHNE Early
%    Stopping. Ein Satz dazu, warum: sonst hinge die effektive
%    Modellkapazität am Zufall des einzelnen Refits.
%  - GF entsteht durch Finetuning des G-Modells bei einem Zehntel der
%    Lernrate. Die Zahl der Finetuning-Epochen wird einmal auf dem Burn-in
%    aus dem Gitter {5, 10, 20, 40} gewählt.
%  - Drei Seeds (42, 43, 44) laufen unabhängig.
%  - Die gewählte Konfiguration am Ende: xLSTM L W=3 / 5 Epochen,
%    G W=24 / 1 Epoche; LSTM L W=3 / 29 Epochen, G W=3 / 10 Epochen.
%    Prüf die vier Werte gegen die Appendix-Tabelle, bevor du sie
%    hinschreibst.
% ZAHLEN AUS: \cref{tab:app_nn_space} (Suchraum),
%   \cref{tab:app_frozen_nn} (eingefrorene Werte), \cref{tab:app_protocol}.

Both LSTM and xLSTM share the same protocol and only deviate in the architecture itself. This is a necessity to attribute the skill difference to the cell and not the pipeline. More details in \cref{sec:models:lstm}. For hyperparameter optimization we use Optuna with TPE sampler, seed 42, 20 start-up trials, 3 warm-up steps, MedianPruner, 100 trials and one study per regime. Per trial we at maximum use 100 epochs and early stopping with patience 15. We freeze the epoch count from the winner trial. Then, for the L regime, we use the median of the best epochs over all 10 countries and for the G regime we use the best epoch. All refits train on that fixed epoch count without early stopping to prevent the model capacity from being dependent on one refit. The GF works by fine-tuning the G model at a tenth of the learning rate. The count of fine-tuning epochs is chosen once on the burn-in set from the grid $\{5, 10, 20, 40\}$. We use three independent seeds (42, 43, 44). (Selected: xLSTM L $W=3$/5 ep., G $W=24$/1 ep.;
LSTM L $W=3$/29 ep., G $W=3$/10 ep.)




\paragraph{LightGBM.}

% SCHREIBE: Absatz LightGBM-Protokoll (5-6 Sätze).
%  - Gleiches Optuna-Protokoll wie oben (TPE, 100 Trials, derselbe Pruner,
%    dieselbe Burn-in-Selektion) — nicht noch einmal ausbreiten, nur
%    referenzieren.
%  - Nur die Regime L und G. BEGRÜNDUNG statt bloßer Feststellung:
%    Gradient Boosting hat kein Finetuning-Analogon, also kann es kein GF
%    geben. Das ist eine Eigenschaft des Verfahrens, keine Auslassung
%    deinerseits — genau so formulieren.
%  - Ein Booster je Quantil.
%  - Der eigentliche Unterschied: LightGBM kann keine Sequenzen
%    verarbeiten. Der Lookback wird deshalb durch eine ex-ante tabulare
%    Lag-Struktur ersetzt — verschachtelte Lag-Sets aus {1,2,3,6,12,24},
%    dazu optional ein Block rollierender Mittel über {3,6,12} Monate.
%  - PFLICHT: unter demselben 24-Monats-Cap wie die Sequenzmodelle. Sonst
%    ist der Vergleich nicht fair und der Absatz verliert seinen Zweck.
%  - Im G-Regime geht das Land als native kategoriale Variable ein.
%  - Early Stopping wirkt hier auf Boosting-Runden, nicht auf Epochen.
% ZAHLEN AUS: \cref{tab:app_lgbm_space}, \cref{tab:app_frozen_lgbm}.

We use the same Optuna protocol as for the neural networks (TPE, 100 trials, the same pruner, the same burn-in selection). But for LightGBM there is no GF regime since there is no fine-tuning analogue for gradient boosting. Per quantile we train one booster. LightGBM cannot process sequential data so we create the lookback via an ex ante tabular lag structure from the nested lag sets $\{1,2,3,6,12,24\}$ with the possibility of added rolling means over $\{3,6,12\}$ months. LightGBM is also subject to the 24-month information cap to make the comparison fair. Early stopping works here on boosting rounds, not epochs.

\paragraph{ARIMA, Random Walk.}

% SCHREIBE: Absatz klassische Baselines (6-7 Sätze).
%  - ARIMA hat nur das L-Regime und wird je Land auf dem differenzierten
%    Target gefittet. Das ist äquivalent zu ARIMA(p,1,q) in Levels.
%  - Schätzung der Koeffizienten per Maximum Likelihood (exakt, über den
%    Kalman-Filter).
%  - Ordnungswahl: (p,q) per AIC über das Gitter {0,...,3}^2, also 16
%    Kandidaten, auf dem Burn-in (Daten bis Monat 114), danach je Land
%    eingefroren.
%  - PFLICHT: daraus folgt, dass diese Modelle NICHT auf einen
%    Punktfehler-Loss wie MAE oder RMSE gefittet werden. Das gehört
%    gesagt, weil man es sonst beim Lesen der Results-Tabellen annimmt.

%  - Der Trend ist unterdrückt (\texttt{trend="n"}), damit ARMA(0,0) den
%    Random Walk nestet. Ein Satz, warum das wichtig ist: der Random Walk
%    ist der Nenner aller Skill-Verhältnisse, also muss er im selben
%    Rahmen liegen und darf kein Fremdkörper sein.
%  - Beide Modelle sind deterministisch. Ihre Prognosequantile kommen aus
%    den empirischen Quantilen der In-Sample-Ein-Schritt-Residuen, nicht
%    aus einem Quantil-Loss.
%  - Abschluss: sie teilen Testfenster und Conformal-Layer mit allen
%    anderen Modellen, aber nichts von der Selektionsmaschinerie.
% ZAHLEN AUS: \cref{tab:app_frozen_arma} (Ordnungen je Land; Frankreich
%   kollabiert auf (0,0), reproduziert also den Random Walk — schöner
%   Konsistenz-Check, den du erwähnen kannst).

ARIMA only employs the L regime and is fitted per country on the difference of the target. This is equivalent to ARIMA$(p,1,q)$ in level space. The coefficients are fitted via maximum likelihood estimation and order $(p,q)$ via AIC over the grid $\{0,\dots,3\}^2$ with 16 candidates on the burn-in set and are frozen per country. The model is not fitted to the MAE or RMSE. The trend is suppressed so that ARMA$(0,0)$ nests the Random Walk. The Random Walk is the denominator of all skill ratios. Both models are deterministic and their prediction intervals come from the empirical quantiles of the in-sample one-step residuals, not a quantile loss. They share the test window and conformal methods with all the other models but not the selection mechanism.

%  - Sie werden genau so verwendet, wie NX-AI sie auf Hugging Face

%  - PFLICHT: ein Satz, warum das eine bewusste Entscheidung ist und

%    Frage, die RQ3 stellt. Sonst liest es sich wie eine Lücke.
%  - TiRex-2 läuft zusätzlich in einer Kovariaten-Variante. Hier NUR die
%    Tatsache nennen und auf \cref{sec:models} verweisen; die Varianten

Both TiRex and TiRex-2 are pretrained zero-shot models so there is no training, refit or hyperparameter tuning. We use them as NX-AI has released them on Hugging Face (\texttt{NX-AI/TiRex}, \texttt{NX-AI/TiRex-2}). This is done to isolate the effect of pretrained vs.\ trained on the same (\texttt{xlstm} vs.\ \texttt{tirex2}) or similar architecture. TiRex-2 also has a variant that takes in covariates. More details in \cref{sec:models}.

\subsection{Seeds and aggregation}
\label{sec:exp:seeds}

% SCHREIBE (7-9 Sätze). Der Absatz hat ZWEI Themen, die im Original
% ineinanderlaufen. Trenn sie — notfalls zwei Absätze.
%
% TEIL A — Seeds:
%  - Nur xLSTM und LSTM laufen mit drei Seeds (42, 43, 44). Alle übrigen
%    (RW, ARIMA, LightGBM, TiRex, TiRex-2) sind deterministisch, ein Seed.
%  - WOZU: sie messen, wie viel vom Ergebnis Trainingszufall ist.

%  - Berichtet wird Coverage als Mittelwert +/- sd über die Seeds, später
%    zusätzlich die Spannweite des Median-Skills als Robustheitscheck.

%  - Hyperparameter werden EINMAL bei Seed 42 getunt (\cref{sec:exp:hpo})
%    und eingefroren -> die Seeds unterscheiden sich nur in den
%    Produktions-Refits, nicht im Tuning.

%  - Jede Seed ist eine eigene Refit-/Predict-Kette; das Seed-Label bleibt
%    an jeder Vorhersagezeile bis durch Conformal- und Diagnostikstufe.
%  - PFLICHT: NIE über Seeds poolen, bevor die Metriken je Kette berechnet
%    sind. Sonst wäre die Seed-Streuung weggemittelt — genau die willst du
%    ja messen.
Only LSTM and xLSTM employ three seeds (42, 43, 44) to measure how much of the result is statistical noise. All the other models (RW, ARIMA, LightGBM, TiRex, TiRex-2) are deterministic and therefore dont need a seed. We report coverage as mean, standard deviation over all seeds and the span of the median skill to check for robustness. The hyperparameters are tuned once at seed 42 (\cref{sec:exp:hpo}) and then frozen. The seeds therefore only differ in the production refits. Every seed is a stand alone refit predict chain. The seed lable stays on every prediction line through the conformal and diagnostic steps. We never pool over seeds before all metrics per chain are calculated otherwise we would average out the seed variation.
% TEIL B — Aggregation:
%  - Level-Metriken (Winkler, Pinball, mittlere Breite, Median-MAE) pro
%    Land, also je Regime, Seed und Land.
%  - BEGRÜNDUNG: sonst dominiert ein Land mit hohem Spread-Niveau. Dasselbe
%    Argument benutzt du in \cref{sec:exp:hpo} ("countries with higher
%    spread levels would dominate") — formulier es hier gleich.
%  - Nur die skalenfreien Metriken (mittlere Coverage-Rate, mittlere
%    Crossing-Rate) werden über Länder gemittelt. Das ist die EINZIGE
%    Länder-Aggregation der Arbeit — dieser Ausschließlichkeitsanspruch
%    ist eine Aussage, steh dazu.

The level matrics (Winkler, Pinball, mittlere Breite, Median-MAE) are calculated per Regime, Seed and country since doing otherwise would lead to one country with high spread niveau dominating. Only the scale free metrics (mean Coverage-Rate, mean Crossing-Rate) are averaged across countrys. This is the only country aggregation in this work.



\subsection{Quantile post-processing}
\label{sec:exp:rearrange}

% SCHREIBE (4-5 Sätze).
%  - Problem: die drei Quantile werden unabhängig geschätzt, sie können
%    sich kreuzen.
%  - WARUM das zählt: gekreuzte Quantile geben der nachgelagerten
%    Conformal-Schicht undefinierte Intervallgrenzen. Das ist der Grund
%    für den ganzen Schritt.
%  - Lösung: die drei Werte werden je Prognose sortiert — monotone
%    Rearrangierung \parencite{chernozhukov2010}, garantiert
%    q_0.1 <= q_0.5 <= q_0.9.
%  - Wie oft die Rohquantile vor dem Sortieren kreuzten, wird als
%    Diagnostik geloggt und je Modell berichtet.
%  - Abschluss: identisch für jedes Modell — Teil der Gleichbehandlung,
%    auf der der Vergleich beruht.
%
% TIPP: Der Absatz ist im Original vier glatte Sätze und sagt nichts

The benchmarks only provide raw quantiles and dont contain calibration code themselfes. The Conformal layer only runs after the raw model output was calculated per model, regime, seed and country. All Methods share the non conformity score $E_t = \max(\hat{q}_{\mathrm{lo},t} - y_t,\; y_t - \hat{q}_{\mathrm{hi},t})$, calibrated on an rolling out of sample pool. Since every Model empys the same methodology the differences in intervall quality can be attributed to the underlying models not the calibration. The methods, their fixed parameters, and
the calibration-pool variants are described in \cref{sec:conformal}.
